Core concepts

Capabilities, specs, synthesis, executors, contracts. Five ideas explain the runtime.

The pipeline

request → capabilities → match agents → synthesize the gaps → graph → tools & data → output

Everything runs through agentmesh.core.runtime.run_project(). The CLI and the FastAPI app are thin wrappers over it, so the two entry points cannot drift.

Capabilities

A request reduces to capabilities — sql_analysis, pii_detection, report_generation. Agents advertise what they cover. Nothing in the runtime hardcodes an agent name.

Known gap, and the biggest one. Capability resolution is still substring keyword matching over a fixed table of 18 capabilities. A request about translation or legal review resolves to report_generation — wrong, and it reports no missing capability. This is the next thing to replace; see the status page.

Agents are YAML

id: sql_analyzer_agent
name: SQL Analyzer Agent
description: Reviews SQL for correctness, safety and performance risks.
capabilities: [sql_analysis, query_review]
tools: [sql_analyze]
depends_on: []
output_contract:
  format: json
  required_fields: [findings, risk_level, suggested_changes, confidence]
models:
  default: anthropic/claude-opus-5
  fallback: [openai/gpt-4.1-mini]

Specs use extra="forbid", so a typo'd key fails at load rather than being silently ignored. The spec is the prompt: description sets the role, capabilities scope the work, tools say what it can do, the contract defines the JSON it must return.

Synthesis

When a required capability has no matching agent, AgentMesh builds one and runs it. The gap is still reported in missing_capabilities, so nothing is hidden — the work just gets done.

┃ ID                       ┃ Origin      ┃ Level ┃
│ domain_research_agent    │ synthesized │   0   │
│ option_generation_agent  │ synthesized │   0   │
│ report_agent             │ spec        │   1   │

Synthesized agents are ephemeral. Re-run with --save-agents to keep them.

Kept agents land in the project's agents/ directory as ordinary specs, so the next run loads them and synthesizes nothing. An agent you keep is indistinguishable from one you wrote. Adapting an existing agent creates a new version of it — see Governance.

Executors

Every spec names an executor; the default generic is model-backed and tool-using. Register your own when an agent needs real code:

@register_executor("sql_analyzer")
class SqlAnalyzerAgent(BaseAgent):
    def run(self, message, context):
        ...

Retries, timing, token accounting and cost live in the call object the broker hands you, so any executor gets all of it free.

Output contracts

required_fields is enforced. Missing fields are attached as contract_violations rather than quietly accepted; unparsable responses are flagged the same way with the raw text preserved.

{
  "agent_id": "sql_analyzer_agent",
  "tools_used": ["sql_analyze"],
  "contract_violations": ["risk_level", "confidence"]
}
