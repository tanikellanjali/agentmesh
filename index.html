A user question in.
A graph of agents out.

AgentMesh is an open-source Python runtime for building internal agent meshes. Agents are YAML specs, not classes. Capabilities nothing covers are synthesized at runtime. Every model call is retried, costed, and logged.

user request → required capabilities → matched or synthesized agents → dependency graph → structured output
Get started View source $ pip install -e ".[dev,providers]"

What it does

The runtime is the product. The CLI and the FastAPI wrapper are two doors into the same run_project() call, so they cannot drift apart.

🧬

Agents that don't exist yet

When a request needs a capability no registered agent covers, AgentMesh writes an agent for it and runs it. Ephemeral by default — saved only when you ask.

🕸️

A real dependency graph

Agents declare depends_on and run in topological levels. Independent agents in a level run concurrently. Cycles fail at build time, not mid-run.

🔌

Bring your own model

Claude and OpenAI adapters behind one provider interface, plus a deterministic mock for offline work. Your keys, your choice of model, per-agent routing.

🔁

Retries that know better

Exponential backoff with jitter on 5xx, connection errors, and rate limits. Auth failures and refusals fail immediately instead of burning attempts.

📊

Every call accounted for

Tokens, cost, attempts, duration, and outcome recorded per model call — not per agent. Human tables or one JSON object per call.

💸

Your budget, your call

There is no default spending cap. AgentMesh will not pick one for you. Set --max-cost when you want a ceiling, and the run stops at it.

Quick start

Python 3.11+. Runs offline with no credentials at all.

1

Install

git clone https://github.com/tanikellanjali/agentmesh
cd agentmesh
pip install -e ".[dev]"

# the providers you intend to use
pip install -e ".[anthropic]"   # Claude
pip install -e ".[openai]"      # OpenAI
2

Run it offline, right now

agentmesh run --project data_ops "Review this SQL query for quality risks" --provider mock
3

Add your own credentials

agentmesh configure-models      # prompts for keys, merges into .env
agentmesh check-models --live   # proves the keys actually work

agentmesh run --project data_ops "Review this SQL query" --max-cost 0.50
No silent fallbacks. If no provider is usable, the run fails with an explicit error naming every attempt. It will never hand you placeholder output dressed up as a real answer.

Agents are YAML

Most agents need no Python at all. A spec with an output contract runs on the generic model-backed executor — the spec is the prompt.

Declare one

id: sql_analyzer_agent
name: SQL Analyzer Agent
capabilities:
  - sql_analysis
  - query_review
depends_on:
  - ingestion_agent
output_contract:
  format: json
  required_fields:
    - findings
    - risk_level
    - confidence
models:
  default: anthropic/claude-opus-5
  fallback:
    - openai/gpt-4.1-mini

Or let the mesh write it

# needs a capability nothing covers?
# AgentMesh synthesizes an agent and runs it
$ agentmesh run -p data_ops "Research the options"

┃ ID                     ┃ Origin      ┃ Level ┃
│ domain_research_agent  │ synthesized │   0   │
│ option_generation_...  │ synthesized │   0   │
│ report_agent           │ spec        │   1   │

# ephemeral — gone when the run ends.
# keep the good ones:
$ agentmesh run -p data_ops "..." --save-agents

Saved agents become ordinary specs on disk, so the next run loads them and synthesizes nothing.

Execution is a graph, not a list

Agents run in dependency levels. An agent with the response_composition capability implicitly waits for everyone else and writes the final answer — so the response comes from the composer, not from whichever agent happened to finish last.

You can see what it cost

Every model call is recorded — not every agent. An agent that retried three times shows three attempts, and the tokens each one burned.

In the terminal

┃ Agent              ┃ Calls ┃ Retries ┃  In ┃ Out ┃ Cost $ ┃
│ data_quality_agent │     1 │       0 │  23 │  30 │ 0.0009 │
│ sql_analyzer_agent │     1 │       0 │  23 │  30 │ 0.0009 │
│ report_agent       │     1 │       0 │ 208 │  30 │ 0.0018 │
│ total              │     3 │       0 │ 254 │  90 │ 0.0035 │

The composer reads 208 input tokens against 23 for the level-0 agents — because it actually receives their output.

Or as JSON, one line per call
