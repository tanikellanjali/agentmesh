Cost & reliability

Every model call and every query is retried where sensible, recorded individually, and counted against a ceiling only if you set one.

Retries

FailureRetriedWhy
5xx from the providerYesServer-side, usually transient
Connection error / timeoutYesTransport, usually transient
429 rate limitYesBackoff is the correct response
401 / 403 auth failureNoA bad key will not become good
Model refusalNoAsking again wastes money
4xx bad requestNoThe request is malformed
agentmesh run -p data_ops "..." --max-attempts 5   # default 3; 1 disables

Per-call telemetry

Records are per model call, not per agent — an agent that retried three times shows three attempts and the tokens each burned. Tool runs and data queries are recorded too.

┃ Agent              ┃ Calls ┃ Retries ┃  In ┃ Out ┃ Cost $ ┃ Tools       ┃
│ data_quality_agent │     2 │       0 │  50 │  68 │ 0.0020 │ query_data  │
│ sql_analyzer_agent │     2 │       0 │  46 │  60 │ 0.0018 │ sql_analyze │
│ report_agent       │     1 │       0 │ 208 │  30 │ 0.0018 │ -           │
│ total              │     5 │       0 │ 304 │ 158 │ 0.0056 │ 3 run       │
agentmesh run -p data_ops "..." --json-logs --log-level INFO
{"run_id": "2467afcf710e", "call_id": "4eabd3f8fe8b",
 "agent_id": "sql_analyzer_agent", "model_key": "anthropic/claude-opus-5",
 "attempts": 1, "outcome": "ok", "duration_ms": 812.4,
 "input_tokens": 8, "output_tokens": 30, "cost": 0.00079}

outcome is ok, tool_use, error, refusal or unparsable. Intermediate failures are kept in retry_errors rather than discarded.

Budgets are yours to set

There is no default spending cap. AgentMesh will not decide your budget. A ceiling exists only when you pass one — separately for models (max_cost) and data (max_data_cost).
agentmesh run -p data_ops "..." --max-cost 0.50   # exit code 2 if it stops
Budget stop: Run ae48555b0f9e reached the \$0.5000 ceiling
(spent \$0.5031) before agent 'report_agent'.

The overshoot caveat

The cap blocks new calls; agents already in flight are not cancelled, so a level running several agents concurrently can overshoot by up to one level's spend. AgentMesh says so rather than hiding it:

Budget overshot: spent \$0.0017 of \$0.0010. Concurrent agents in one level can
exceed the cap; use --max-workers 1 for a strict ceiling.

Failures don't stop the mesh

An agent whose call fails after its retries returns a structured error with confidence: 0.0, and the rest of the graph continues. You get a partial answer plus a clear record of what broke, instead of a stack trace and nothing.

Timeouts

Every model call carries a timeout, defaulting to 120 seconds and configurable per model in the routing table. A timeout is treated as transient, so it retries under the same policy.

anthropic/claude-opus-5:
  timeout_s: 60
A timeout has a default where a budget deliberately does not: an unbounded hang is a defect, not a policy choice.

Run persistence

agentmesh run -p data_ops "..." --save-run
.runs/2467afcf710e/
  run.json             # request, plan, graph, usage
  llm_calls.jsonl      # one row per model call
  tool_runs.jsonl
  data_ops.jsonl
  agent_outputs.jsonl
  final_response.json

Split so each file is useful alone, and JSONL so a run loads straight into a table.
