Cost & reliability

Every model call is retried on transient failures, recorded individually, and counted against a ceiling only if you set one.

Retries

Exponential backoff with jitter. What matters is what gets retried:

FailureRetriedWhy
5xx from the providerYesServer-side, usually transient
Connection error / timeoutYesTransport, usually transient
429 rate limitYesBackoff is the correct response
401 / 403 auth failureNoA bad key will not become good
Model refusalNoAsking again wastes money
4xx bad requestNoThe request is malformed
agentmesh run -p data_ops "..." --max-attempts 5   # default 3; 1 disables

Retries happen inside the metered call object, so an executor gets them without writing any retry code, and the attempt count lands in telemetry either way.

Per-call telemetry

Records are per model call, not per agent — an agent that retried three times shows three attempts and the tokens each one burned.

┃ Agent              ┃ Model                   ┃ Calls ┃ Retries ┃  In ┃ Out ┃ Cost $ ┃
│ data_quality_agent │ anthropic/claude-opus-5 │     1 │       0 │  23 │  30 │ 0.0009 │
│ sql_analyzer_agent │ anthropic/claude-opus-5 │     1 │       0 │  23 │  30 │ 0.0009 │
│ report_agent       │ anthropic/claude-opus-5 │     1 │       0 │ 208 │  30 │ 0.0018 │
│ total              │                         │     3 │       0 │ 254 │  90 │ 0.0035 │

Structured logs

agentmesh run -p data_ops "..." --json-logs --log-level INFO
{"ts": "2026-09-23T02:08:49", "level": "INFO", "logger": "agentmesh.llm",
 "run_id": "2467afcf710e", "call_id": "4eabd3f8fe8b",
 "agent_id": "sql_analyzer_agent", "provider": "anthropic",
 "model_key": "anthropic/claude-opus-5", "model": "claude-opus-5",
 "attempts": 1, "outcome": "ok", "duration_ms": 812.4,
 "input_tokens": 8, "output_tokens": 30, "cost": 0.00079,
 "error": null, "retry_errors": []}

outcome is one of ok, error, refusal, or unparsable. Intermediate failures are kept in retry_errors rather than discarded.

Budgets are yours to set

There is no default spending cap. AgentMesh will not decide your budget for you. A ceiling exists only when you pass one.
agentmesh run -p data_ops "..." --max-cost 0.50

When the ceiling is reached the run stops and exits with code 2:

Budget stop: Run ae48555b0f9e reached the $0.5000 ceiling
(spent $0.5031) before agent 'report_agent'.

The overshoot caveat

The cap blocks new calls. Agents already in flight are not cancelled, so a level running several agents concurrently can overshoot by up to one level's spend. AgentMesh says so rather than hiding it:

Budget overshot: spent $0.0017 of $0.0010. Concurrent agents in one level can
exceed the cap; use --max-workers 1 for a strict ceiling.

Add --max-workers 1 when the ceiling must be exact.

Failures don't stop the mesh

An agent whose model call fails after its retries returns a structured error output with confidence: 0.0, and the rest of the graph continues. You get a partial answer plus a clear record of what broke, instead of a stack trace and nothing.

{
  "agent_id": "sql_analyzer_agent",
  "summary": "SQL Analyzer Agent could not complete: OpenAI rate limited...",
  "confidence": 0.0,
  "error": "OpenAI rate limited the request: ..."
}

Not built yet

  • Per-call timeouts — a hung provider currently blocks its level
  • Run persistence — telemetry is structured but not yet written to .runs/
