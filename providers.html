Models & credentials

You choose the provider and the model, and you supply the keys. AgentMesh routes each agent to one, and never substitutes a fake model when the real one is unavailable.

Built-in providers

NameBackendRequires
anthropicClaude, via the official anthropic SDKANTHROPIC_API_KEY + .[anthropic]
openaiOpenAI, via the official openai SDKOPENAI_API_KEY + .[openai]
mockDeterministic, no networknothing
localAlias for mock until an Ollama adapter landsnothing

Both SDKs are optional and lazily imported. A missing SDK or a missing key produces a named error, not an ImportError halfway through a run.

Supplying credentials

agentmesh configure-models

Prompts for the keys you have plus an optional default provider and model, then merges them into .env. Keys already in the file are preserved, so adding OpenAI later will not wipe your Anthropic key. .env is gitignored.

Credentials are read from .env and the process environment. Precedence for choosing a model:

  1. --provider / --model on the command
  2. AGENTMESH_PROVIDER / AGENTMESH_MODEL in the environment
  3. The agent spec's own models.default, then each models.fallback

Verifying they work

agentmesh check-models --project data_ops
┃ Routing key              ┃ Provider  ┃ Credentials ┃
│ anthropic/claude-opus-5  │ anthropic │ ok          │
│ mock/deterministic       │ mock      │ ok          │
│ openai/gpt-4.1-mini      │ openai    │ OPENAI_A... │

Add --live to send one tiny real request per provider, which is the only way to tell a well-formed key from a working one.

Model routing

Each project has a models/model_routing.yaml. A stable routing key maps to a provider, the provider's real model id, and per-token cost — so a vendor renaming a model is a one-line change, not a sweep through every agent spec.

models:
  anthropic/claude-opus-5:
    provider: anthropic
    model: claude-opus-5
    cost_per_1k_input_tokens: 0.005
    cost_per_1k_output_tokens: 0.025
    max_tokens: 4096
  openai/gpt-4.1-mini:
    provider: openai
    model: gpt-4.1-mini
    cost_per_1k_input_tokens: 0.0004
    cost_per_1k_output_tokens: 0.0016
Verify the pricing. The numbers shipped in the example pack are a starting point. Check them against each vendor's current price list before trusting a cost report.

Fallback chains actually degrade

An agent's models.fallback list is tried in order. A provider that cannot be constructed — missing SDK, missing key — is skipped for the next candidate.

models:
  default: anthropic/claude-opus-5
  fallback:
    - openai/gpt-4.1-mini

If nothing in the chain is usable, the run stops and tells you every candidate it tried:

No usable model for agent 'sql_analyzer_agent'
  (anthropic/claude-opus-5 -> anthropic: ANTHROPIC_API_KEY is not set.;
   openai/gpt-4.1-mini -> openai: OPENAI_API_KEY is not set.).
Run `agentmesh configure-models`, or use --provider mock to run offline.
The chain never ends at a mock. Degrading to fake output would make a broken configuration look like a working one. Use --provider mock when you want that, explicitly.

Writing a provider

A provider implements one method and returns usage alongside the text:

from agentmesh.providers import register_provider

class MyProvider:
    name = "my-provider"

    def complete(self, *, system, prompt, model, max_tokens=4096, effort=None):
        return Completion(text=..., provider=self.name, model=model, usage=Usage(...))

register_provider("my-provider", MyProvider)

Raise ProviderTransientError for anything worth retrying and ProviderAuthError for anything that isn't — see Cost & reliability.
