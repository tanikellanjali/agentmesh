Status & roadmap

v0.1.0, 81 passing tests. This page is the real state of the project, not a roadmap dressed up as a changelog.

What works

CapabilityStateNotes
YAML specs, registry, capability matchingWorkingStrict validation; typo'd specs fail loudly
Dynamic agent synthesisWorkingDeterministic — not yet model-written
Opt-in agent persistenceWorking--save-agents; ephemeral otherwise
Dependency graph + concurrencyWorkingTopological levels, cycle detection
Claude providerWorkingTested against real SDK response objects
OpenAI providerWorkingNot yet verified against the live API
Retries with backoffWorkingTransient failures only
Per-call telemetry & costWorkingTokens, attempts, duration, outcome
Opt-in budget ceilingsWorkingConcurrent levels can overshoot; --max-workers 1 is strict
Output-contract validationWorkingViolations reported, never hidden

What doesn't

GapImpact
Per-call timeoutsA hung provider blocks its level indefinitely
Run persistence under .runs/Telemetry is structured but lost when the process exits
API authenticationThe FastAPI app must not be exposed publicly
LLM-based synthesisSynthesized agents are templated, not reasoned about
Capability resolutionKeyword matching over request text; brittle and hard to scale
Ollama / local providerlocal is currently an alias for the mock
CI pipelineNo GitHub Actions, linter, or type checker configured yet
agentflow extraReferences packages not on PyPI; the install fails

Next up

  1. Per-call timeouts — the last thing between this and an unattended run you can trust
  2. Run logs under .runs/ — the telemetry is already structured for it
  3. Model-written synthesis — richer agents drafted from the request, not a template
  4. A real capability resolver — replacing keyword matching
  5. CI — Actions matrix on 3.11–3.13, ruff, mypy

Contributing

The gaps above are the best places to start. Small, well-tested PRs are easiest to review.
