Tools & MCP

An agent that cannot act is a classifier. AgentMesh agents call real tools — built-in ones, and any tool exposed by an MCP server.

Built-in tools

Dependency-free and real: they do the analysis themselves rather than asking a model to guess.

ToolWhat it does
sql_analyzeWrites without WHERE, SELECT *, leading-wildcard LIKE, functions on indexed columns, implicit cross joins, NOT IN subqueries — severity ranked
pii_scanEmails, phones, SSNs, IPs, API keys and Luhn-validated credit cards. Returns masked samples, never the raw value
redact_textReplaces every match, right to left so offsets stay valid
profile_csvTypes, nulls, cardinality, quartiles, duplicates, constant columns — via DuckDB when installed
describe_dataWhat data is bound to this agent, and its real schema
query_dataRead-only SQL against bound data, aggregated at the source
estimate_query_costPrice a query before running it
text_statsSize checks

Declaring tools on an agent

id: sql_analyzer_agent
tools:
  - sql_analyze
  - query_data

A tool the agent declared but that does not exist is reported as tools_unavailable in the output rather than failing the run.

The loop

The model is offered its tools, calls what it needs, receives real results, and keeps going until it answers. A tool that raises is reported back to the model as an error so it can retry with different arguments — it does not kill the run.

model → tool_use → execute → result → model → … → answer

Retries, timing and cost live in the call object, so any executor you write gets them free. At the iteration limit tools are withheld and the model must answer with what it has.

Writing a tool

from agentmesh.tools import register_tool

@register_tool(
    name="margin_by_supplier",
    description="Compute gross margin per supplier over bound transactions.",
    input_schema={"type": "object", "properties": {}, "additionalProperties": False},
)
def margin_by_supplier(ctx):
    return ctx.table("transactions").query(
        "SELECT supplier, SUM(units*(sale_price-unit_cost)) AS margin "
        "FROM {table} GROUP BY supplier"
    ).summary()
A tool whose first parameter is ctx is handed the agent's data context. The model never sees it, and never sees a credential.

MCP servers

MCP is the emerging standard for connecting models to tools and data, with servers for Postgres, BigQuery, Slack, GitHub and hundreds more — many maintained by the vendors themselves. AgentMesh speaks it rather than reimplementing that long tail.

from agentmesh.tools.mcp_bridge import McpServer, register_mcp_tools

with McpServer("inventory", command="python", args=["inventory_server.py"]) as server:
    register_mcp_tools(server)
    # -> ['inventory.reorder_list', 'inventory.stock_level']

Discovered tools become ordinary ToolSpecs, namespaced by server so two servers can expose the same name. An agent declares them like any other tool:

tools:
  - inventory.reorder_list
  - sql_analyze          # built-in and MCP side by side
SDK versions differ. MCP 2.x renamed FastMCP to MCPServer and moved to snake_case field names. The bridge reads both generations, so a project pinned to mcp<2 still works.
pip install -e ".[mcp]"
